# Auto Translate Article

**App Action** function triggered by Contentful Workflow Automations. When an entry hits a designated workflow step, the automation invokes this function; the function invokes a published **AI Action** once per (field × target locale) and writes translations back as a draft.

Same wiring pattern as `compliance-review`.

## Files

Source-only — no per-app `package.json`, `node_modules`, or `.env`. All build deps + credentials live at the repo root.

```
auto-translate-article/
├── contentful-app-manifest.json     ← declares one App Action function
```

## Setup

### 1. Create an AI Action

**Settings → AI Actions → Create action.** Configure:

- **Prompt** (example):
  > Translate the following content from the source locale to `{{targetLocale}}`. Preserve tone, formatting, and any brand terms. Return only the translated content.
  >
  > Content:
  > {{content}}
- **Variables**:
  - `content` — Text
  - `targetLocale` — Text
- **Output format**: PlainText (or Markdown / RichText — must match the app config).

Publish the AI Action. Copy its ID.

### 2. Build & upload the app

Everything runs from the repo root — no per-app `package.json` or `node_modules`. The build script uses `@contentful/app-scripts` from the root dependencies.

```bash
# From the repo root:
npm run ctf-app:build  -- auto-translate-article    # compile only
npm run ctf-app:upload -- auto-translate-article    # compile + upload
```

Required env vars in the repo-root `.env` (gitignored):

```
CTF_MANAGEMENT_TOKEN=<your CMA token>
CTF_ORGANIZATION_ID=<org id>
CTF_APP_AUTO_TRANSLATE_ARTICLE_APP_DEF_ID=<app definition id>
```

The upload script reads these and passes them to `contentful-app-scripts upload`.

### 3. Install in Contentful

- Install this app to the target environment.
- On the **Config screen**, fill in:
  - **Content type IDs** — e.g. `article, blogPost` (empty = every type)
  - **Source locale** — e.g. `en-US`
  - **Target locales** — e.g. `de, fr, es, it`
  - **Localizable fields** — `title, summary, body`
  - **AI Action ID** — from step 1
  - **Output format** — matches the AI Action's setting
  - **Skip existing** — leave on so reviewer edits aren't clobbered
  - **Publish after update** — off by default (safer)

### 4. Create an App Action linked to this function

In the Contentful UI (or via CMA): create a new **App Action** whose target is the `Auto Translate Handler` function. Set `type: function-invocation` and `category: Custom` with no parameters (the automation body already carries `entryId` / `environmentId` / `spaceId`).

### 5. Create a Workflow + Automation

- Create a Workflow with a step like **"Ready to translate"**.
- Create an **Automation** on that step transition — action target: the App Action from step 4.
- Save.

## Runtime flow

1. Author moves an entry into "Ready to translate".
2. Contentful Automation fires, calling the App Action.
3. Function receives `{ entryId, environmentId, spaceId }` in the body.
4. Function:
   - Loads the entry via CMA.
   - Applies the content-type allowlist.
   - For each `(field × targetLocale)`, invokes the AI Action.
   - Bounded parallelism (`MAX_CONCURRENCY = 4`).
   - Polls each invocation until `COMPLETED` (or `FAILED` / timeout).
   - Writes translations back as **draft** (or publishes if `PUBLISH_AFTER_UPDATE = true`).
5. Reviewers approve each locale and publish.

## Why App Action (not AppEvent)

App Actions match the shape of this repo's compliance-review app and Contentful's Workflow Automations. Editors get:

- Explicit control — the automation only fires on the workflow step you choose (not every publish).
- A stable trigger point that can be reused for retries / manual invocation.
- A clean audit trail in the Automations UI.

## Design decisions

- **Idempotent-ish.** By default, target locales already populated are skipped so reviewer edits aren't clobbered. Toggle off in config to overwrite.
- **Draft-only writes** unless `PUBLISH_AFTER_UPDATE = "true"`. Prevents auto-publishing unreviewed AI output.
- **Bounded concurrency (`MAX_CONCURRENCY = 4`).** Keeps well inside the function timeout, avoids AI backend rate limits.
- **Distinct error paths.** `FAILED`, `CANCELLED`, and timeout each raise specific messages. Partial failures don't nuke the batch — every successful translation applies, failures are logged.

## Tunables (constants at the top of `auto-translate-handler.ts`)

| Constant | Default | Purpose |
|---|---|---|
| `MAX_CONCURRENCY` | 4 | Parallel AI Action invocations |
| `INVOCATION_TIMEOUT_MS` | 25000 | Per-invocation polling timeout |
| `POLL_INTERVAL_MS` | 750 | Initial polling interval (gentle backoff after) |

Everything else — content types, locales, fields, action id, skip/publish policy — is configured via the app's Config screen and read from `context.appInstallationParameters` at runtime.

## Notes for demo prospects

Not every customer uses AI translation. This function is a template — swap the AI Action for a call to Google Translate / DeepL by changing only the invocation body; the surrounding pattern (bounded concurrency, poll, draft-write) stays the same.
